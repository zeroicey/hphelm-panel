# 双主机看板：ssh 长连接 + 远端只读探针（不在生产机上装东西）

**状态：** ✅ ACCEPTED（2026-10-21，用户裁决）

## 背景

面板原来只显示本机。用户要求「增加生产服务器监控……在一块屏幕上同时显示本机跟生产服务器的资源监控」，
并给出三条口径：进程榜只占一列、两台同页一人一半、**不做轮播**。

## 选项

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **A. ssh 长连接 + 远端 perl 探针**（选中） | 生产机上**零安装**（脚本从 stdin 喂入、只读 `/proc`）；远端实测 0.3% of one core；掉线可重连 | 依赖 ssh 免密；探针是 perl（Debian 自带，不需装） |
| B. 同一份 C 代码编译成静态二进制装到生产机 | 数值口径与本机完全一致 | 要在生产机上放可执行文件 —— 违反「hpcore 必须干净」 |
| C. node_exporter + HTTP 拉 | 标准做法、生态最全 | 生产机上常驻一个服务 + 开端口，占用最大 |

## 决定

选 **A**。配套的硬约束：

1. 探针**只读** `/proc`、`/sys`；不写文件、不装包、不起服务、不开端口
2. **一条长连接**，不是每秒 ssh（每次建连 ~100ms + 握手 + 远端 fork 一个进程）
3. fd 直接进主循环的 `poll`，**不引入第三个线程**
4. **只在面板可见时跑**（桌面/登录页停掉子进程），但保留已采到的快照
5. `E` 行结尾才提交整帧 ⇒ 视图读不到撕裂状态
6. 退避重连 2→4→8→16→30 秒；断线显示「离线 Ns」，不阻塞主循环

## 后果

- 面板多一个外部依赖：本机 `ssh` + 生产机的 `perl`（Debian/Arch 都自带）
- 生产机的负载会多 0.3%（可忽略，但要知道）
- 探针输出格式是**跨机器契约**：改 `S`/`C`/`P` 行必须同时改 `src/remote.c` 的解析
  （解析器对字段数不足的行会**静默丢弃**，版本不匹配时表现为「一直没有数据」）
- 用户明确否决轮播 ⇒ 不做相位/动画，内容签名与「不闪」判据保持不变
