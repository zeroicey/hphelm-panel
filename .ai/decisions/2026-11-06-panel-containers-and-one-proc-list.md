# 面板第二版：一条进程榜 + 一块容器区，曲线降高

**状态：** ✅ ACCEPTED（2026-11-06 下午，用户直接给出口径）

- 补充 `2026-11-06-single-host-panel.md`（单机化的思路不变，只改「榜怎么排、空间怎么分」）

## 背景

单机化上线后用户给的四条（原话）：

> 「我没搞懂 你为什么要搞两个一模一样的进程 列表 你直接整列显示 二十多个不就好了吗
> 另外两列空余空间也很多 一个折线图占位太多了 继续想办法 先把那个进程列表搞定吧
> 也不用占那么大空间吧 你可以把我们的 Docker 容器都列出来呀 搞一块地方 显示资源占用之类的」

问题是真的：上段「按内存 12 行」与下段「按 CPU 12 行」画的是**同一批进程**，字段完全一样
（名次/名称/pid/内存/CPU%），只有顺序不同 —— 一行信息被花了两行版面。而 hpcore 是 all-in-one，
**容器是这个机队唯一真正在跑的东西**，面板里却只有一个「容器 23」的数字。

## 选项

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **A. 一条 CPU 榜（25~26 行）+ 容器块 + 曲线降到 150**（选中） | 一行不再画两遍；容器占用有了名字；CPU 榜按 CPU% 排序，空载时数值全接近 0，排序自然退化成内存榜 —— 两段榜单想要的信息一条榜全给了 | 只有按 CPU 一种排序口径（用户要「清单」，不要「四种切法」） |
| B. 保留两段，改成「按内存 12 + 按线程 12」 | 版面还是两段 | 线程数探针没有（`P` 行只带 rss/cpu），等于编数据 |
| C. 容器做成独立一幕 | 空间大、能放 23 个 + 历史曲线 | 用户要的是「搞一块地方」，不是第三幕；而且幕轮换 30s，切走就看不见 |

## 决定

选 **A**，三件配套：

1. **一条榜**：`view_panel_draw()` 只调一次 `draw_proc_list()`，数据用 `m->top_cpu`（探针 `Q` 行 40 条，
   无阈值），行数按可用高度算 `(bottom - BODY_Y - TITLE_H - 10) / ROW_H`（1080p 下 25 行）。
   每行同时给内存与 CPU%；`cpu_pct < 0`（老探针）画 `-`，`0.0%` 是真值。
2. **容器块**：探针新增 `D <总数> <合计MiB> <name>:<memMiB>:<cpu%>,…`（每 3 秒，按内存取 12 个）。
   数据源是 cgroup v2 的 `docker-*.scope/{memory.current,cpu.stat}`；**名字只能从 `docker.sock`
   翻**（`GET /containers/json?all=1`，缓存 300s，失败不覆盖旧表）。面板横跨主机区整宽，
   两个子列各 5 个。**本机模式不画容器块**（名字要 socket，C 里不值得再写一份 docker 客户端）。
3. **曲线降高**：`L_H_CHART_MAX 260 → 150`，`L_HOST_FRAC 0.56 → 0.66`（进程榜只有三列，
   529 宽会空一大片）。1080p 实测：`wa=399.2 ch=138.4 FIX_A=FIX_B=187 余=0.0`。

## 后果 / 代价

- 探针契约多一行 `D`，`Q` 从「24 条 ≥2%」变成「40 条无阈值」 ⇒ 老面板（`.prev`）仍能工作
  （它不认 `D`/多出的 `Q` 条目，只是少画），新面板对老探针降级为「无容器块 + 无 CPU%」。
- `docker.sock` 打不开（happpy 不在 docker 组、或探针不是 root）时容器块整块消失 ⇒ 曲线自己长回去
  （`ctr_h = 0`），不留一块空洞。
- 容器 CPU 用 cgroup `usage_usec` 差值算，**与进程榜的 CPU% 不同源**（前者是容器总占用，
  后者是进程瞬时占用），两处数字不相等是正常的。

## 已知未做

- 容器只按内存取前 12 个（面板画 10 个）；要「按 CPU 排容器」得再加一行契约。
- 容器健康度（restart 次数、OOM、退出码）没做 —— 需要 `docker inspect` 或 cgroup 的 `memory.events`。
- `docker.sock` 是 root only；如果哪天探针降权跑到普通用户，容器块会静默消失。
