# 单机面板：面板只画一台机（all-in-one hpcore），进程榜整列归它

**状态：** ✅ ACCEPTED（2026-11-06，用户直接给出口径）

- 取代 `2026-10-21-dual-host-dashboard-over-ssh.md` 的「两台同屏」部分（探针机制本身仍有效）
- 取代 `2026-10-21-three-column-layout.md` 的三列数（仍是无卡片 + 流式排版的思路）

## 背景

用户口径（2026-11-06）：**「hpcmd 下线了，现在所有都是 all in one hpcore 了，所以那一幕你看看
显示点啥比较好，全显示 hpcore 相关东西，把空间占满，进程那一列可以全部给他了。」**

现状：`hpcmd`（`192.168.5.51`）已经不可达，配置里 `remote=hpcore` + `remote2=hpcmd`，
左列永远 `● 离线 55983s`；而三列版式下每张曲线只有 96 逻辑像素高、CPU 3% 时曲线贴着底，
上方 ~90 像素恒为空 ⇒ 三列里有一列全死、其余两列大片留白。

## 选项

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| **A. 单机 + 主机区左右两个子列 + 进程榜整列**（选中） | 每张曲线 219 像素高；进程榜从 24 条（两机各 12）变成一台机 24 条（内存榜 + CPU 榜）；行宽不变（子列 ≈336），右对齐数值不会离标题太远 | 少一个「第二台机」的位置（但**没有第二台机了**） |
| B. 一台机占满整宽、不分子列 | 实现最简单 | 一行拉成 700 像素宽，标签与数值相距 400 像素，读不过来 |
| C. 保留三列，左列显示本机（hpopi5b 自己） | 保留「面板宿主自身」的健康度 | 用户明确说「全显示 hpcore 相关东西」；Pi 自身的 CPU/内存对他没意义 |

## 决定

选 **A**，并顺带三件配套：

1. **删掉 `remote2` 全套**（`CFG_REMOTE2`/`R2`/`FEED2`/`env->r2`/`env->feed2`/poll 第三源）。
   `--remote2` 与 `remote2=` **仍然接受**，但只打一行「已废弃，已忽略」—— 万一有老启动脚本/老 conf
   （hpopi5b 上那份就是），报错退出会让 kiosk 黑屏，这比多留一行解析代码贵得多。
2. **进程榜加「按 CPU」一段**：`proc_row_t` 加 `cpu_pct`，本机（`read_procs`）与远端探针
   （`P` 行扩成 4 段 + 新增 `Q` 行）各自按 `utime+stime` 差值算。面板按冒号段数兼容老格式，
   老探针没有这一列时显示「-」而不是假 0。
3. **曲线加刻度底**（`v_chart_scale`）：25/50/75% 三条极淡细线 + 右上角量程 + 列底一行
   「近 5 分钟 · 1 Hz 采样」。理由：0~100 固定量程下，CPU 3% 的曲线会贴着基线走，
   上面两百像素纯白会被读成「这块没画东西」。

## 后果

- 探针契约变了（`P` 的字段数 + 新增 `Q`）⇒ **面板与探针必须同版本**。老面板读新探针：
  `parse_proc_row` 按段数分支 ⇒ 3 段也认，不影响。新面板读老探针：CPU 列显示「-」。
- `LAYOUT_DEBUG=1` 的判据改成看 `FIX_A == FIX_B == 187` 与 `余=0.0`（两列固定高度相等）。
- 想恢复双机，需要重新引入 `remote2` + 三列版式；曲线仍可保留 `v_chart_scale`。
