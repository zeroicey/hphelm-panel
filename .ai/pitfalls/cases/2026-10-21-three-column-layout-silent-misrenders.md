# 三列版式的三个静默错版（编译零告警，只有量像素才发现）

**状态：** ✅ 已解决（2026-10-21，加第二台主机那一轮）

这一轮把面板从「三栏 + 进程榜」改成「本机 │ 生产 │ 进程榜」，一口气踩了三个**都不报错**的错版。
记下来是因为它们的共同点：**代码跑得很正常，日志很干净，判据全绿，但屏幕上就是错的**。

## 1. 纵向坐标按「相对」写，实际当「绝对」用

`theme.h` 里的注释写的是「相对 `L_BODY_Y` 的偏移」，但常量值是绝对值（44 / 126 / 166 …），
而 `view_panel.c` 又写成了 `py = L_BODY_Y + 26`。

**结果**：CPU 标题画在主机名**上面**（y=104 的标题 vs y=58 的主机名，视觉上标题压在名字上），
整列内容比设计低 100 像素，最底下的磁盘/容器信息被推出屏幕。

**判据**（唯一能抓住它的方法）：按列切一条竖带，量「墨迹带」的 y 起点，和设计表逐行对：

```sh
python3 tools/measure.py shot.png --bands --bands-crop 27,50,648,1030 --bands-min 3
# 期望：96(主机名) 160(角色行) 201(CPU标题) … 每一条都要能在设计表里找到对应行
```

**修法**：常量全部改成绝对逻辑像素，并在 `theme.h` 里留一张「纵向预算表」当量像素时的对照表。
注释和实现必须描述同一件事 —— 否则注释比没有更危险。

## 2. 本机列被「远端未连上」的早退分支截断

`draw_host()` 用 `age_s < 0` 表示「远端还没收到第一帧」，于是提前 `return` 并显示
「正在建立 ssh 连接…」。但**本机的 `age_s` 也传 -1**（本机没有「年龄」概念）⇒
本机列只画出主机名和角色行，下面全空。

**结果**：左列只有两行文字，右列（远端连上了）完整。看着像「本机采集坏了」。

**修法**：加一个显式的 `is_remote` 参数。**不要用「某个数值的特殊值」兼职表示语义**
（-1 既是「本机」又是「还没连上」，这种重载一定会出错）。

**判据**：两张截图 —— 一台在线、一台故意配错主机名（`--remote no-such-host-xyz`）——
**本机列必须两次完全一样**。

## 3. 进程名截断切裂 UTF-8

第一版按字符数硬截：

```c
snprintf(nm, sizeof nm, "%.*s…", maxch - 1, m->top[i].name);  /* ❌ 可能切在多字节中间 */
```

中文/日文进程名被切一半 ⇒ pango 画豆腐块或干脆不画（**静默**）。

**修法**：`v_truncate_mono()` 先按字符宽估算截断点，再**退到 UTF-8 边界**
（`0x80..0xBF` 是续字节，不能当结尾）。

**判据**：给它喂中文名 + 三个不同宽度，检查输出能正常渲染：

```c
v_truncate_mono(out, sizeof out, "磁盘守护进程名字很长很长", v_fd_proc(), 60);
// → "磁…"（而不是半个字节 + 豆腐块）
```

## 共同教训

> **加宽/加列这类版式改动，必须重新量几何，不能复用上一版的判据。**
> 编译零告警 + 帧差分 0 + 进程不崩 = 完全不能说明版面是对的。
> 三条里只有第 2 条能被「看着不对」发现；第 1、3 条必须靠量像素/单测。
