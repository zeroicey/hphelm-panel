# 看缩放过的截图判版面：我把「曲线在框内」误读成「曲线掉到框外」三次

**Severity:** 🟡 low（只是浪费了两轮改版）· **First hit:** 2026-11-06 · **Hits since:** 3 次

## 症状

看完截图我连续三次判定「布局错位」，三次都**不是**：

1. 「刻度 100% 画到曲线底部去了」→ 实际在 `y + 2`（顶部），是我把缩略图的像素坐标当逻辑坐标。
2. 「CPU 曲线掉到网格框下面了」→ 实际在框内（5% 贴着基线 340，曲线在 315~336）。
3. 「容器块最后一行被屏幕切掉」→ 实际最低墨迹在 703 逻辑像素，屏高 730、下边距 18，没切。

三次的代价：两次无谓的 rebuild + 部署 + 真屏截图往返。

## 根因

截图是 1920×1080 **物理**像素，版面坐标是 **逻辑**像素（`SCALE=1.48`），而且我给模型看的图可能
再被缩放到 1600 或别的宽度显示。人眼在这种缩放图上估 y 坐标，误差 ±20 物理像素 = ±13 逻辑像素，
正好和「一个 gridline 间距（35）」同量级 ⇒ **任何偏移都显得像 bug**。
再叠一层：中文/拉丁混排的墨迹上下不对称，看起来「更歪」。

## 修法（当前做法）

先算，再量，最后才看图：

1. **先算**：`LAYOUT_DEBUG=1` 把预算打出来（`wa=399.2 ch=138.4 FIX_A=187 FIX_B=187 余=0.0`），
   `余=0.0` 说明纵向预算闭合，再拿 `y` 逐个手推每个块的位置。
2. **再量**：`tools/pngcrop.py` 直接数像素 —— 找 gridline（某行浅灰像素 > 半宽）、
   找曲线（某行紫色像素 > 0）、找内容最低行（某行深色像素 > 3），换算成逻辑像素：
   ```sh
   python3 tools/pngcrop.py shot.png --runs 300            # 某一行的游程 ⇒ 定位竖细线/条
   # 或 import load_png 后自己数（见 HANDOFF 第十三/十四轮的命令）
   ```
3. **最后看图**：只用来判断「好看不好看」，**不用来测坐标**。

## 守卫

- 判据里凡是「位置」类问题（对齐/是否越界/是否重叠），一律给**数字**（逻辑像素），不给「看起来」。
  已有先例：圆点落在墨迹中线那道判据写的是 `109.0 == 109.0`。
- `docs/verify.md` 第五节已经写明「看不到图怎么验」；补一条：**缩放图的坐标不可信**。
- 版面常量全在 `src/theme.h`，改版面先改常量再算一遍 `FIX_A == FIX_B`。
