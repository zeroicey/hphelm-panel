# 设计系统：无卡片 · 紧凑 · Catppuccin Mocha

> 改 UI 先读这份。核心原则只有三句：**不用卡片**、**标题不占行**、**坐标只写在 `theme.h`**。
> 相关：[`architecture.md`](architecture.md)（渲染机制）· [`verify.md`](verify.md)（怎么量）

---

## 一、三条硬原则

### 1. 不用卡片

**没有圆角框、没有底色块。** 分区只靠三样东西：

| 手段 | 怎么用 |
| --- | --- |
| **1px 细线**（`v_rule()`） | 只在「带与带之间」画，全宽；颜色 `C_SURFACE1 @ 0.45` |
| **字号层级** | 标题 11pt / 值 9~10pt / 大数值 26pt / 进程行 14pt |
| **留白** | 栏间 26 逻辑像素、带间 12 逻辑像素 |

原先的 `v_panel_box()`（圆角框 + `C_MANTLE@62%` 填充）**已删除**，不要加回来。

### 2. 紧凑：标题不单独占行

区块标题（如「CPU」「内存」「网络」）与它的右侧数值（如 `57.6°C`）**在同一行**，左标题右数值。
顶栏只有一行。系统三栏并排而不是上下堆。

### 3. 坐标只写在 `theme.h`

任何 `view_*.c` 里出现 `L_xxx` 常量以外的布局数字（除了栅格内相对偏移）都算坏味道。
**主机列的纵向是流式的**（`y` 一行行累加，常量在 `theme.h` 的 `L_H_*`），不再写死每个区块的绝对 y ——
加监控项时只要往流里插一段，不会被顶出屏幕。
绘制全程在**逻辑像素**下进行，主循环统一 `cairo_scale(SCALE)`；`SCALE` = 物理/逻辑（本机 1.48）。

## 二、版式常量（`src/theme.h`）

本机：1920×1080 物理 / 141.8 DPI ⇒ `SCALE=1.48` ⇒ **逻辑屏 ≈1297×729**。

### 单机结构（2026-11-06 起：hpcmd 下线，all-in-one 到 hpcore）

用户口径：「hpcmd 下线了，现在所有都是 all in one 到 hpcore 了，那一幕你看看显示点啥比较好，
全显示 hpcore 相关东西，把空间占满，进程那一列可以全部给他了」。

⇒ 面板从「本机 │ 生产 │ 生产2 │ 进程榜」缩到**一台机 + 一整列进程榜 + 一块容器区**。
（第二版，2026-11-06 下午，用户口径：「两个一模一样的进程列表」「一个折线图占位太多了」
「可以把我们的 Docker 容器都列出来呀，搞一块地方显示资源占用」）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `L_MARGIN` | 18 | 页面外边距 |
| `L_COL_GAP` | 26 | 主机区与进程列之间的间距（竖细线画在它的中点） |
| `L_TOP_Y` / `L_RULE1_Y` | 12 / 46 | 顶栏文字 / 顶栏下细线 |
| `L_HOST_FRAC` | 0.66 | **主机区**宽度占比（≈832 逻辑像素 ⇒ 两个子列各 ≈399）；进程列吃剩下的 34% |
| `L_SUB_GAP` | 34 | 主机区内左右两个子列的间距（容器块用同一个） |
| `L_PROC_TITLE_H` | 28 | 进程榜标题行高 |
| `L_PROC_ROW_H` | 24 | 进程榜行高 |
| `L_PROC_MAX` | 26 | 进程榜行数上限（实际行数按可用高度算：`(bottom - BODY_Y - TITLE_H - 10) / ROW_H`） |
| `L_CTR_GAP` | 18 | 主机块与容器块之间的空隙 |
| `L_CTR_TITLE_H` | 24 | 容器块标题行 |
| `L_CTR_ROW_H` / `L_CTR_ROWS` | 22 / 5 | 一行高 / 每个子列几行（共 10 个） |
| `L_CTR_PAD_B` | 16 | 容器块下沿留白（贴着物理屏边会像被切掉） |

⚠️ **进程榜只有一条**（2026-11-06 下午改）：早期版本是「按内存 12 行 + 按 CPU 12 行」两段，
同一台机画两遍、字段还能对不上，用户直接点评「两个一模一样的进程 列表」。现在**一列一条榜**：
按 CPU% 降序（同值比 RSS），每行同时给出内存与 CPU%，行数由可用高度算到 25~26 行 ——
空载时 CPU% 全接近 0，排序自然退化成「内存榜」，不需要两段。
CPU% 为**负数**表示老探针没有这一列（画 `-`，不要冒充 0.0%）。

**进程列宽度是算出来的**（`mw - host_w - COL_GAP`），不写常量 ——
`const double w[3] = {a, b, 0}` 那种「宽度写 0」的错版不会报错，只会画出一根线（我们踩过）。

### 主机区内部：**左右两个子列 + 流式排版**

一台机独占整块宽度会把每一行拉成 700 像素长、右对齐的数值离标题 400 像素远（读不过来）。
所以主机区分成左右两个子列（各 ≈399 逻辑像素），**同一个 `draw_host()` 画**：

- 左子列：名称/状态 → 身份行 → 细线 → CPU（行/条/每核柱/曲线）→ 内存（行/条/曲线）
- 右子列：网络（行/双曲线）→ 磁盘 I/O（行/双曲线）→ 细线 → 磁盘用量（行/条）→ 细线 →
  容器/线程/进程 → 累计流量 → 细线 → PSI 压力（+ 盘累计读写）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `L_H_NAME_Y` | 58 | 子列内第一行的顶部（= `L_BODY_Y`） |
| `L_H_NAME_H` | 36 | 主机名行高（与身份行拉开） |
| `L_H_IDENT_H` | 20 | 身份行（角色/IP/up/核数/网卡） |
| `L_H_RULE_H` | 8 | 细线上下的留白合计 |
| `L_H_LINE_H` | 24 | 一个资源行的行高（标题 + 数值**同排**） |
| `L_H_BAR_H` / `L_H_BAR_GAP` | 10 / 9 | 进度条高度 / 与下一行的间距 |
| `L_H_CORES_H` | 28 | 每核柱高度（>16 核自动两行） |
| `L_H_CHART_MIN` / `L_H_CHART_MAX` | 30 / 150 | 曲线高度的夹取范围（上限 2026-11-06 从 260 降到 150：用户说「一个折线图占位太多」，腾出的高度给容器块） |
| `L_H_CHART_GAP` | 6 | 曲线与其下内容的间距 |
| `L_H_SYS_H` | 24 | 右下角三行小字（容器/线程/进程、累计、PSI）的行高 |
| `L_H_CAP_H` | 16 | 曲线时间轴说明行（「近 5 分钟 · 1 Hz 采样」），两个子列各一条 |

**两个子列各两张曲线，均分剩余高度**，1080p 下 `ch = 138.4` 逻辑像素、底部余量 **0**；
主机块下面还压着容器块（`ctr_h = 18+24+5×22+16 = 168`）。

⚠️ **两列固定高度必须相等**：`FIX_A`（左列：名称+身份+细线+CPU 区+内存行/条）
与 `FIX_B`（右列：2 行 + 细线 + 磁盘行/条 + 细线 + 2 小字行 + 细线 + 1 小字行）都必须是 **187**。
差 1 像素，两列的曲线基线就错开一截，而**编译零告警**。判据：

```sh
LAYOUT_DEBUG=1 ./hpopi5b-panel --state panel 2>&1 | grep HOST
# HOST 18: wa=336.2 ch=219.4 FIX_A=187 FIX_B=187 余=0.0
#                                              ↑ 必须是 0（负数 = 已经超出底部留白）
```

⚠️ **曲线要有刻度底**（`v_chart_scale()`，2026-11-06 加）：单机化后曲线高 138~219 像素，
而 CPU 平时只有 3%、内存 40% ⇒ 线贴着底走，上方两百像素纯白 —— 会被读成「这块没画东西」。
所以每张曲线都画 25/50/75% 三条极淡细线（α 0.42 / 0.24）、右上角量程（百分比或 `v_fmt_rate`，
垫一块底色避免被峰顶压住），并在列底用一行小字写时间跨度。
量程由 `v_chart_scale()` 返回、**再显式传给 `v_spark()`** —— 否则网格和曲线各算一套量程。

⚠️ **第 4 格曾经是温度曲线，2026-11-05 换成了磁盘读写速率**：温度在 CPU 行已经有一份
`58.2°C` 文本（曲线是重复展示）；而没有 `k10temp` 的机器（自研 KVM guest 的
`/sys/class/hwmon` 整个是空的、Pi 的 hwmon 叫 `soc_thermal`）这一格**永远空白** —— 留白
会被误读成「读不到数据」，实际上一点数据都不缺。磁盘速率是每台机都采的维度，
而且它就坐在磁盘块正上方，读图不用猜。曲线共享量程（teal=读 / peach=写，与网络同规矩），
所以「写」远小于「读」时会贴着基线——这是**同量纲对比**的本意，不是画丢了。

### 对齐细节：小圆点必须落在文字的**墨迹中线**上

状态圆点（本地/在线/离线）原来用经验值 `y + 8` 定位，看起来「偏上」。
根因是字体的 `ascent` 不随字号线性变化，而且 CJK 与拉丁的下伸部不同 ⇒ 任何常数都会差 1~2 像素。

正解是 `v_text_right_ex()`：它**在画这一行的同一次排版里**取出墨迹 extents，把中线返回给调用方：

```c
double tw = 0, mid = 0;
v_text_right_ex(cr, x + w, ty, v_fd_label(), stc, &tw, &mid, "%s", sts);
v_dot_at_text(cr, x + w - tw - 8, ty + mid, 3.2, stc);   /* 圆心 = 文字墨迹中心 */
```

**判据**（量像素，不靠肉眼）：截一张图，取圆点的 bbox 中心与同一行文字的墨迹中心，
两者 y 必须相同。实测两列都是 `109.0 == 109.0`。

## 四、曲线（sparkline）规范

```c
void v_spark (cr, x, y, w, h, ring, col, vmax);              // 单曲线
void v_spark2(cr, x, y, w, h, r1, c1, r2, c2, vmax);         // 双曲线共用同一量程
double v_nice_ceil(double v);                                 // 量程吸附 1/2/5×10ⁿ
```

四条规矩：

1. **量程必须稳定**：用 `v_nice_ceil()` 吸附到 1/2/5×10ⁿ。
   否则「历史最大值」一变，整条曲线就整体跳一下（用户会看成「在抖」）。
   CPU / 内存传固定 `100.0`。
2. **不预填**。⛔ 不要用「当前值」把环形缓冲填满来治「起步为空」：
   那个值来自启动瞬间的 120ms 窗口，实测常是 **0**、偶尔是**突发尖峰** ⇒
   曲线要么贴底、要么被假尖峰把量程顶上去把真数据压扁。**这是伪造历史。**
3. **空态用零基线**：`spark_base()` 在底部画一条 `C_SURFACE1@30%` 的线 ⇒
   看起来是「0 值」而不是「坏了」；曲线本身从右侧诚实生长（跟 htop 一样）。
   真要「一开机就铺满」，正解是**缩短窗口**（只画最近 N 个样本）。
4. **双曲线共用量程**：上下行放一起比较才有意义（`v_spark2` 自动取两者最大值再 nice 化）。

窗口：`RING_CAP = 300` 点 @ 1 Hz = **5 分钟**。

## 五、进度条与每核柱

- `v_bar()`：自带轨道（`C_SURFACE0@85%`），高度 10~12 逻辑像素，圆角 = 高/2。
  CPU 用 mauve、内存用 blue、磁盘用 teal（≥90% 转 red）。
- `v_core_bars()`：
  - **带轨道**（否则空闲时柱高 1px，根本看不见 —— 用户原话之一）；
  - **最低 2px 亮条** ⇒ 空闲核也能看出「这里有核、现在是 0%」；
  - 颜色随负载：`>80%` red / `>50%` peach / 其余 blue；
  - `>16` 核自动分两行。

## 六、登录页

与面板**同一套无卡片风格**：整屏渐变底 + 居中的「时钟 / 日期 / 主机信息 / 细线 / 用户名 / 密码框」。

- **没有外层卡片**（原来那个 `C_MANTLE` 圆角框已删）。
- 唯一保留的「框」是**密码输入框本身** —— 它是输入控件，不是装饰性卡片。
- 认证中（`busy`）：一行「正在验证…」+ **不确定态进度条**（相位取自 `m->now`）。
- 出错：红字 + 「N 秒后可重试」。
- 光标：2Hz 闪烁（主循环里 `(int)(now_s()*2) % 2`）。

## 六·五、性能：一帧 5~10ms 花在哪（2026-10-21 实测）

面板 1 Hz 重绘，**单帧绘制时间 × 1 Hz ≈ CPU 占用**（这台机上 10ms/帧 ≈ 1% of one core）。
所以改 UI 时顺手看一眼 `HPOPI5B_PANEL_DEBUG=1` 的「绘制 Xms」。三个已知大头：

| 大头 | 现象 | 已做的处理 |
| --- | --- | --- |
| **pango 整形次数** | 一帧 100+ 次（主机区 8 行 + 24 行进程） | 右对齐/居中**复用同一次排版**取宽度（`v_text_right_w`）；进程名按字符宽估算截断 |
| **整屏渐变填充** | 每帧 4~5ms（cairo pattern 在 Xlib 表面上掉进客户端渲染） | 渐变只渲染进一张 `bgpix`，每帧用一次 `XCopyArea` 复制过来 |
| **进程榜逐字符测量** | 每删一个字符量一次宽度 ⇒ 每帧几百次整形 | 等宽字体 ⇒ `v_char_w()` 量一次「MMMMMMMMMM」除 10 |

⚠️ **量 CPU 前先看 load average**。本轮我在 `load average: 22.99`（无关的 go 编译）时量了几轮，
数字全部作废 —— 量到的是别人的负载，不是面板的。判据必须写清「同一时刻的 load」才有可比性。

## 七、改版式的检查清单

改完必须量（见 [`verify.md`](verify.md)）：

- [ ] 整屏 ASCII 里没有「空栏」「叠字」「越界」
- [ ] 每核柱：根数 = 核数，宽度/间距与常量算出来的一致
- [ ] 进程榜：**一整列一条榜**（25~26 行，按 CPU%），行距 24 逻辑像素，内存/CPU% 两列右对齐到固定列位
- [ ] 容器块：主机区整宽、两个子列各 5 个，名字不截断（`v_truncate_mono` 按子列宽算），内存与 CPU% 右对齐
- [ ] 主机区两个子列的曲线**基线在同一 y**（`FIX_A == FIX_B == 187`，差 1px 就错开）
- [ ] `LAYOUT_DEBUG=1` 的「余」必须是 **0.0**（负数 = 已超出屏幕底部）
- [ ] 状态圆点的 bbox 中心 y == 同一行文字的墨迹中心 y—— 用一个 `draw_host()` 就是为了这个
- [ ] 曲线有零基线，且没有贴到下一根细线上
- [ ] 每块标题与数值在**同一行**（没有独立的标题行）
- [ ] 登录页无卡片、输入框居中、认证中进度条在动
- [ ] 顶栏时间精度到秒（证明面板 1 Hz 在跑）

⚠️ **`const double w[3] = {a, b, 0}` 这种「宽度写 0」不会报错**，只会画出一根线或什么都不画
（踩过：网络栏宽度 0 ⇒ sparkline 压成竖线、右对齐文字挤到左边缘，编译零告警）。
